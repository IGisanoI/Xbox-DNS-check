# DNS Checker

Настольный инструмент техподдержки для сетевой диагностики DNS и Xbox Live.
Python + CustomTkinter, Windows.

**Важно:** программа не может доказать с офисного ПК, что вход заработает на консоли
абонента. Она находит DNS, которые стоит попробовать, и отдельно сохраняет реальный
результат, сообщённый с консоли. Полная аутентификация Xbox OAuth/XSTS в этой версии
не выполняется.

## Что умеет

### Вкладка «Xbox»

- Проверяет домены Xbox Live через выбранные DNS: резолв → TCP → TLS с SNI и
  проверкой сертификата → HTTP-запрос.
- Делает один повтор при временной ошибке DNS, TCP, TLS или HTTP.
- Отправляет корректные по форме запросы авторизации с заведомо недействительными
  токенами. Ожидаемые ответы 400/401 показывают достижимость сервиса, а не успешный вход.
- Различает ожидаемый ответ, отказ 403/451, перенаправление, неожиданный HTTP-код,
  ошибку сервера 5xx, проблемы TLS и malformed-ответ.
- Показывает попытки, категории, заголовки и начало тела ответа в подробностях проверки.
- По RDAP определяет владельца IP и проверяет через `whoami.akamai.net`, кто на самом
  деле отвечает на DNS-запросы.
- Использует осторожные итоги:
  - **«Стоит попробовать»** — сетевой кандидат с этого ПК, нужна проверка на консоли;
  - **«Регион неясен»** — получен прямой ответ Microsoft, но региональные правила не проверены;
  - **«Под вопросом»** — есть сомнительные критичные проверки;
  - **«Не подходит»** — найдена критичная сетевая проблема;
  - **«Не отвечает»** — DNS не отвечает из этой сети.
- Не считает прямой адрес Microsoft автоматической блокировкой и не считает шлюз
  доказательством обхода. Без настоящих токенов причина 403 и региональный результат
  неизвестны.
- Кнопка **«Ответ абоненту»** создаёт осторожный текст с парой DNS и предупреждением
  о сторонних DNS. Свой шаблон сохраняется при обновлении.
- Фоновое наблюдение сообщает об изменении сетевых кандидатов, а не об «исправлении Xbox».
- История `xbox_log.csv` содержит ID запуска и общие сведения о сети. При смене столбцов
  старый CSV сохраняется как `.bak`, данные переносятся.

### Сетевые профили для всей команды

Кнопка **«Сеть»** задаёт только общий тип подключения: **Офис / Дом / VPN / Другое**,
плюс редактируемое нейтральное название. Личные профили сотрудников не нужны.

По желанию программа определяет организацию текущей сети через ipify и RDAP. Публичный
IP используется только в памяти для запроса, не попадает в отчёт и не сохраняется в кэш.
Сам внешний сервис, естественно, видит адрес, с которого пришёл HTTPS-запрос.

Программа **не меняет** VPN, DNS Windows, настройки роутера или консоли. Поэтому ручной
DNS домашнего роутера не конфликтует с её запросами: тест явно обращается к каждому
выбранному DNS. VPN всё равно влияет на маршрут, доступность и внешнюю сеть, поэтому
результаты из TTK и Goodline нельзя считать одинаковыми.

### Анонимный результат с консоли

После звонка абонента сотрудник нажимает **«Результат на консоли»** и выбирает:

- DNS из последней проверки и необязательный второй DNS;
- «Вход заработал», «Та же ошибка», «Другая ошибка» или «Неизвестно»;
- где меняли DNS: на консоли, роутере, в обоих местах или неизвестно;
- необязательный точный код ошибки.

Отчёт содержит только технические поля: случайные ID отчёта и запуска, время UTC,
результат, код ошибки, место настройки, DNS, тип и нейтральное название сети,
организацию сети, сетевой итог и версию приложения.

**Не собираются:** имя сотрудника, Windows username, имя ПК, публичный IP, данные
абонента и свободные заметки об абоненте. Сетевой результат и результат на консоли
остаются разными видами доказательства.

Каждый отчёт сначала записывается локально и попадает в очередь. Отправка повторяется
после нового отчёта и при следующем запуске. Успехом считается только явный ответ
приёмника `{ "ok": true }`; HTML-страница входа или молчаливый HTTP 200 не считаются
доставкой. Одинаковый ID отчёта не создаёт дубль в таблице.

### Вкладка «Серверы»

- Быстрая проверка доступности DNS с автоповтором и CSV-логом.
- Общий список серверов: перетаскивание, переименование двойным кликом, сортировка.

## Общая таблица через Google Apps Script

Сервер с публичным IP не нужен. Сотрудникам не нужны Google-аккаунты: их приложения
отправляют HTTPS POST на один развёрнутый Apps Script, а он пишет в лист `Reports`.

**Текущая установка:** приёмник развёрнут и проверен на живом тестовом отчёте.
Одна тестовая строка появилась на листе `Reports`, а повторная отправка того же ID вернула
`duplicate: true` и не создала вторую строку. Рабочая таблица:
[DNS Checker — Anonymous Console Feedback](https://docs.google.com/spreadsheets/d/1reT3phPARRX2s39ZorcU_t-rBa-Rux499g4QzFPgBko/edit).
В ZIP релиза 4.0 уже находится рабочий `cloud_config.json`, поэтому облачная отправка
готова сразу после распаковки. Это осознанный вариант для пилота: общий токен доступен
всем, кто скачает ZIP. При появлении спама нужно заменить токен в Script Properties и
в конфигах приложений, а при необходимости сделать репозиторий приватным. В исходном
коде на GitHub реальный `cloud_config.json` не хранится.

Для создания нового отдельного приёмника:

1. Создайте пустую Google таблицу и скопируйте её ID из URL.
2. Откройте **Расширения → Apps Script** и вставьте содержимое `cloud/Code.gs`.
3. В **Project Settings → Script Properties** добавьте:
   - `SHEET_ID` — ID таблицы;
   - `INGEST_TOKEN` — длинную случайную строку, общую для приёмника и приложений.
4. Выберите **Deploy → New deployment → Web app**:
   - **Execute as:** Me;
   - **Who has access:** Anyone.
5. Скопируйте URL, оканчивающийся на `/exec`.
6. Рядом с `DNS-Checker.exe` создайте `cloud_config.json` по образцу
   `cloud_config.example.json`: вставьте URL и тот же токен.
7. Отправьте тестовый отчёт и убедитесь, что строка действительно появилась в `Reports`.
8. Раздайте коллегам одинаковую папку программы с этим конфигом. Не публикуйте реальный
   токен в репозитории или открытом доступе.

Токен в JSON POST нужен потому, что Apps Script не предоставляет произвольные HTTP-заголовки
в объекте события. Это общий секрет ingestion, а не полноценная система учётных записей.
Неверные данные и неверный токен отклоняются. Значения записываются как текст, чтобы
не допустить формулы в ячейках. Дубли определяются по `report_id` под блокировкой скрипта.

Если интернет или Google временно недоступен, отчёт остаётся в `feedback_outbox.json`.
Не удаляйте этот файл до подтверждения доставки.

## Что ПК не проверяет

Даже удачный сетевой тест не воспроизводит настоящий Xbox OAuth/XSTS, NAT, MTU, IPv6,
прошивку консоли, состояние аккаунта и внешний адрес стороннего шлюза. Для Goodline
нужны отдельные измерения из сети Goodline, например при включённом рабочем VPN с явно
выбранным профилем «VPN». Это не заменяет проверку на консоли абонента.

## Запуск из исходников

Проверенная сборка использует Python 3.12.16; код рассчитан на Python 3.10+.

```bash
pip install -r requirements.txt
python dns_checker_gui.py
```

## Сборка .exe

```bat
build.bat
```

Готовая программа появится в `dist\DNS-Checker\`. Скопируйте `cloud_config.json`
рядом с `.exe` после настройки Google.

## Файлы рядом с программой

| Файл | Что внутри |
|---|---|
| `servers.txt` | список DNS-серверов (адрес и название) |
| `consoles.json` | домены Xbox и ожидаемые HTTP-ответы |
| `reply_template.txt` | шаблон ответа абоненту (`{dns1}`, `{dns2}`) |
| `settings.json` | настройки окна, вкладок и общего профиля сети |
| `ip_owners.json` | кэш RDAP владельцев IP на 7 дней; не кэш публичного IP |
| `dns_log.csv` | лог вкладки «Серверы» |
| `xbox_log.csv` | сетевая история вкладки «Xbox» |
| `console_feedback.csv` | локальная история анонимных результатов консоли |
| `feedback_outbox.json` | отчёты, ожидающие подтверждённой доставки |
| `cloud_config.json` | приватный endpoint и ingestion token; не входит в репозиторий |

## Структура проекта

```text
dns_checker_gui.py        точка входа
dnschecker/
  config.py               серверы, домены Xbox, ожидаемые ответы, шаблон
  paths.py                пути рабочих файлов
  storage.py              файлы и миграции старых данных
  dns_tools.py            DNS-запросы и проверка «кто отвечает»
  http_probe.py           TCP → TLS → HTTP, классификация ответов
  owners.py               владелец IP через RDAP
  network.py              общие профили сети и определение организации
  feedback.py             анонимные отчёты, CSV, очередь, HTTPS-доставка
  xbox.py                 сетевые проверки и осторожный вердикт
  server_list.py          общий список серверов и сортировка
  reply.py                текст ответа абоненту
  ui/                     интерфейс CustomTkinter
cloud/Code.gs             приёмник Google Apps Script
tests/                    автономные тесты логики и локального HTTP
```

## Тесты

```bash
pip install pytest
python -m pytest -q
```

Сетевые ответы в тестах имитируются; HTTP-запросы проверяются через локальный сервер.
Они не требуют консоли, внешнего интернета или Google. Apps Script выполняется только
в Google, поэтому его реальную доставку нужно проверить после развёртывания.
